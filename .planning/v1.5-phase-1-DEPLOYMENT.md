## LinkedIn App Setup

### 1. Create LinkedIn App

1. Go to [LinkedIn Developer Portal](https://www.linkedin.com/developers/)
2. Click **Create app**
3. Fill in app details:
   - App name: ResumeAI
   - Company: Your company
   - App logo: Upload logo
4. Accept terms and create

### 2. Configure OAuth

1. Go to **Auth** tab
2. Add redirect URI: `https://yourdomain.com/auth/linkedin/callback`
3. Add test accounts (for development)
4. Note Client ID and Client Secret

### 3. Enable Products

1. Go to **Products** tab
2. Request access to:
   - **Sign In with LinkedIn** (auto-approved)
   - **r_liteprofile** (auto-approved)
   - **r_emailaddress** (auto-approved)
3. Wait for approval (usually instant)

### 4. Apply for Partner Program (Optional)

For Jobs API and Easy Apply:
1. Go to [Partner Program](https://www.linkedin.com/developers/partner-program)
2. Submit application
3. Wait for approval (2-4 weeks)

## Staging Deployment

### 1. Deploy to Staging

```bash
# Set staging environment
export ENVIRONMENT=staging
export LINKEDIN_CLIENT_ID=staging_client_id
export LINKEDIN_CLIENT_SECRET=staging_client_secret
export LINKEDIN_REDIRECT_URI=https://staging.yourdomain.com/auth/linkedin/callback

# Deploy
docker-compose -f docker-compose.staging.yml up -d

# Check health
curl https://staging-api.yourdomain.com/api/v1/health
```

### 2. Run Smoke Tests

```bash
# Test OAuth initiation
curl -X POST https://staging-api.yourdomain.com/api/v1/linkedin/connect \
  -H "Authorization: Bearer YOUR_TEST_TOKEN"

# Expected: { "authorization_url": "...", "state": "..." }

# Test connection status (not connected)
curl https://staging-api.yourdomain.com/api/v1/linkedin/status \
  -H "Authorization: Bearer YOUR_TEST_TOKEN"

# Expected: { "isConnected": false }
```

### 3. Manual Testing

1. **OAuth Flow:**
   - Click "Connect with LinkedIn"
   - Complete OAuth flow
   - Verify connection established

2. **Profile Import:**
   - View imported profile
   - Select sections to import
   - Verify data in resume

3. **Refresh:**
   - Click "Refresh"
   - Verify profile updated

4. **Disconnect:**
   - Click "Disconnect"
   - Verify connection removed

### 4. Verify Monitoring

```bash
# Check logs

# Check metrics
curl https://staging-api.yourdomain.com/metrics

grep -i "error" /var/log/resume-api/*.log
```

## Production Deployment

### 1. Pre-Deployment

```bash
# Backup database
pg_dump -h localhost -U resumeai resumeai > backup_$(date +%Y%m%d).sql

# Verify backup
pg_restore --list backup_$(date +%Y%m%d).sql

# Set production environment
export ENVIRONMENT=production
export LINKEDIN_CLIENT_ID=production_client_id
export LINKEDIN_CLIENT_SECRET=production_client_secret
export LINKEDIN_REDIRECT_URI=https://yourdomain.com/auth/linkedin/callback
```

### 2. Deploy

```bash
# Run migrations
alembic upgrade head

# Deploy new version
docker-compose up -d --force-recreate resume-api

# Wait for health check
until curl -f http://localhost:8000/api/v1/health; do sleep 1; done
```

### 3. Post-Deployment Verification

```bash
# Health check
curl https://api.yourdomain.com/api/v1/health

# Test OAuth
curl -X POST https://api.yourdomain.com/api/v1/linkedin/connect \
  -H "Authorization: Bearer YOUR_TOKEN"

# Check metrics
curl https://api.yourdomain.com/metrics | grep linkedin
```

### 4. Monitor

Watch for these metrics in first 24 hours:

| Metric | Alert Threshold |
|--------|-----------------|
| OAuth error rate | >5% |
| Token refresh failures | >10% |
| API latency p95 | >2s |
| Connection rate | <20% in 24h |

## Rollback Procedure

### If Issues Occur

```bash
# 1. Stop new deployment
docker-compose stop resume-api

# 2. Restore previous version
docker-compose up -d resume-api:previous_version

# 3. Verify rollback
curl https://api.yourdomain.com/api/v1/health

# 4. Check version
curl https://api.yourdomain.com/api/v1/health | jq .version
```

### Database Rollback (if needed)

```bash
# Restore from backup
psql -h localhost -U resumeai resumeai < backup_YYYYMMDD.sql

# Or downgrade migration
alembic downgrade -1
```

```python
# Connection metrics
linkedin_connections_active

linkedin_api_latency_seconds

# Token metrics
linkedin_tokens_refreshed_total
linkedin_tokens_expired_total
```

### Alert Configuration

```yaml
# Prometheus alerts
groups:
  - name: linkedin_integration
    rules:
      - alert: LinkedInOAuthHighErrorRate
        expr: rate(linkedin_oauth_failed_total[5m]) / rate(linkedin_oauth_initiated_total[5m]) > 0.05
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "LinkedIn OAuth error rate high"
          
      - alert: LinkedInAPIHighLatency
        expr: histogram_quantile(0.95, rate(linkedin_api_latency_seconds_bucket[5m])) > 2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "LinkedIn API latency high"
          
      - alert: LinkedInTokenRefreshFailures
        expr: rate(linkedin_tokens_refreshed_total{status="failed"}[5m]) > 0.1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "LinkedIn token refresh failures"
```
