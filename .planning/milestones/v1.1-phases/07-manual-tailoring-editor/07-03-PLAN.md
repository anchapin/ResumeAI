# Phase 7: Manual Tailoring Editor - Plan 03

**Goal:** Implement change tracking to distinguish AI-suggested changes from manual edits.

**Requirement:** JOB-07

**Success Criteria:**
1. Visual indicators for AI-suggested vs manual changes
2. Toggle to show/hide AI suggestions
3. Accept/reject individual AI changes
4. Merge manual edits with AI suggestions
5. Change history with author attribution

**Dependencies:** Plan 01 (Rich Text Editor), Plan 02 (Version History)

**Out of Scope:** Collaborative editing (future phase)

---

## Tasks

### Task 1: Add Change Tracking Data Structure

**What:** Create data model to track changes with metadata

**Implementation:**
- Create `src/types/change-tracking.ts`
- Define `Change` interface: id, author, timestamp, content, status
- Define `TrackedContent` type: original, modified, changes[]
- Add change tracking to resume store state
- Add selectors for filtering changes by author/status

**Verification:**
- TypeScript types defined
- Changes can be stored with metadata
- Selectors filter by author (AI vs manual)
- Unit tests pass

**Files to create:**
- `src/types/change-tracking.ts`

**Files to modify:**
- `src/store/resume-store.ts`
- `src/store/types.ts`

---

### Task 2: Track AI Suggestions as Changes

**What:** Mark AI tailoring suggestions as tracked changes

**Implementation:**
- Modify `applyAITailoring()` to create Change records
- Set author: 'ai', status: 'pending'
- Store original content alongside suggestion
- Add change ID for tracking
- Update UI to show pending changes

**Verification:**
- AI changes create Change records
- Original content preserved
- Changes marked as pending
- Can query pending AI changes

**Files to modify:**
- `src/store/resume-store.ts`
- `src/utils/ai-tailoring.ts`

### Task 4: Add Accept/Reject Controls

**What:** UI controls to accept or reject individual AI changes

**Implementation:**
- Add Accept (✓) and Reject (✗) buttons next to AI changes
- Add "Accept All" and "Reject All" buttons in toolbar
- Update change status on accept/reject
- Remove highlights after decision
- Show toast confirmation

**Verification:**
- Accept button applies change permanently
- Reject button reverts to original
- Accept All processes all pending changes
- Changes removed from tracking after decision

**Files to create:**
- `src/components/editor/ChangeControls.tsx`

**Files to modify:**
- `src/components/editor/RichTextEditor.tsx`
- `src/store/resume-store.ts`

### Task 5: Add Show/Hide Suggestions Toggle

**What:** Toggle to show or hide AI suggestions

**Implementation:**
- Add "Show Suggestions" toggle in toolbar
- When off, display original content without AI highlights
- When on, display all AI suggestions with highlights
- Persist toggle state in localStorage
- Keyboard shortcut (Ctrl+Shift+S)

**Verification:**
- Toggle visible in toolbar
- Turning off hides AI suggestions
- Turning on shows all suggestions
- State persists across refresh

**Files to modify:**
- `src/components/editor/EditorToolbar.tsx`
- `src/store/resume-store.ts`

---

### Task 6: Merge Manual Edits with AI Suggestions

**What:** Handle conflicts when user edits content with pending AI changes

**Implementation:**
- Detect when user edits content with pending AI changes
- Option 1: Auto-accept AI change, then apply manual edit
- Option 2: Prompt user to resolve conflict
- Option 3: Keep both as separate change layers
- Implement Option 1 for simplicity
- Log conflict in change history

**Verification:**
- User can edit content with pending AI changes
- Manual edit takes precedence
- Conflict logged in history
- No data loss

**Files to modify:**
- `src/store/resume-store.ts`
- `src/components/editor/RichTextEditor.tsx`

---

**Verification:**
- Panel shows chronological change list
- Filters work correctly
- Search finds matching changes
- Clicking scrolls to change in editor

**Files to create:**
- `src/components/editor/ChangeHistoryPanel.tsx`

## Notes

- Change tracking is complex - keep implementation simple
- Use unique IDs for each change (UUID or timestamp-based)
- Consider performance with many tracked changes
- Clean up old changes after accept/reject to save memory
- TipTap has extension API for tracking - consider using it
