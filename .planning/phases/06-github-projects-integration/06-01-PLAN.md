# Plan 06-01: GitHub Repositories API (Backend)

**Phase:** 06-github-projects-integration
**Requirement:** JOB-06
**Goal:** Create backend API endpoints for fetching user's GitHub repositories

## What's Involved

### 1. API Endpoints

Create new endpoints in the existing GitHub routes for repository operations:

**GET `/github/repositories`** - List user's repositories
- Authentication: Required (JWT Bearer token)
- Query Parameters:
  - `page` (number, default: 1): Page number
  - `per_page` (number, default: 30, max: 100): Results per page
  - `type` (string, default: "all"): Filter by "all", "owner", "member"
  - `sort` (string, default: "updated"): Sort by "created", "updated", "pushed", "full_name"
  - `direction` (string, default: "desc"): Sort direction "asc" or "desc"
- Response: Array of repository objects with pagination metadata

**GET `/github/repositories/:owner/:repo`** - Get single repository details
- Authentication: Required
- Path Parameters:
  - `owner`: Repository owner username
  - `repo`: Repository name
- Response: Full repository details including README, languages, contributors

**GET `/github/repositories/:owner/:repo/readme`** - Get repository README
- Authentication: Required
- Response: README content (decoded from base64)

### 2. Response Models

Create Pydantic models for API responses:

```python
class GitHubRepoResponse(BaseModel):
    id: int
    name: str
    full_name: str
    description: Optional[str]
    html_url: str
    language: Optional[str]
    stargazers_count: int
    forks_count: int
    topics: List[str]
    updated_at: str
    created_at: str
    pushed_at: str
    private: bool
    fork: bool
    owner: GitHubOwnerInfo

class GitHubOwnerInfo(BaseModel):
    login: str
    avatar_url: str
    html_url: str

class GitHubRepoListResponse(BaseModel):
    repositories: List[GitHubRepoResponse]
    total_count: int
    page: int
    per_page: int
    has_more: bool
```

### 3. Integration with Existing GitHub Client

Use the existing `GitHubAPIClient` in `resume-api/lib/github_api_client.py`:
- Reuse `list_repos()` method for fetching repositories
- Add `get_repository()` method if not exists
- Add `get_readme()` method for fetching README content

### 4. Error Handling

- **401 Unauthorized**: Invalid/expired GitHub OAuth token
- **403 Forbidden**: Rate limit exceeded (include retry-after header)
- **404 Not Found**: Repository not found
- **500 Internal Server Error**: Network errors, unexpected failures

Implement graceful degradation:
- Return cached data if available when rate limited
- Include rate limit headers in response

### 5. Caching Strategy

Implement simple in-memory caching to minimize API calls:
- Cache repository list for 5 minutes
- Cache individual repo details for 15 minutes
- Cache key: `github:repos:{user_id}:{params_hash}`

## API Usage Example

```bash
# List repositories
curl -X GET "http://localhost:8000/api/v1/github/repositories?page=1&per_page=30" \
  -H "Authorization: Bearer $JWT_TOKEN"

# Get single repository
curl -X GET "http://localhost:8000/api/v1/github/repositories/octocat/Hello-World" \
  -H "Authorization: Bearer $JWT_TOKEN"

# Get README
curl -X GET "http://localhost:8000/api/v1/github/repositories/octocat/Hello-World/readme" \
  -H "Authorization: Bearer $JWT_TOKEN"
```

## Notes

- GitHub API rate limit for authenticated users: 5,000 requests/hour
- Unauthenticated: 60 requests/hour (we always use OAuth so this doesn't apply)
- Consider implementing background sync job for frequently accessed repos
- Future enhancement: Support for GitHub Enterprise instances
