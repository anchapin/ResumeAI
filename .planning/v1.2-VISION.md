# v1.2 Analytics Dashboard - Vision Summary

**Created:** 2026-03-12
**Status:** Milestone Initialized, Ready for Research

---

## User Vision

A job seeker applies to 50+ positions and hears back from only 2. They don't know:
- Why their resume was rejected
- If their resume is ATS-friendly
- Which applications to follow up on
- What skills they're missing for their target role

**v1.2 solves this** by providing:

1. **Job Match Scoring** — "Your resume matches this job 67%. Add these 3 skills to reach 85%."
2. **ATS Check** — "Your resume has 4 ATS issues. Fix these formatting problems before applying."
3. **Application Tracker** — "You have 3 applications pending follow-up. 2 interviews scheduled this week."
4. **Insights Dashboard** — "Your top skills: Python, React, FastAPI. Apply to 5 more jobs this week."
5. **A/B Testing** — "Variant A got 3x more interviews than Variant B. Use Variant A."
6. **Benchmarking** — "Your profile is in the top 40% for Senior Backend roles. Salary range: $120k-$160k."

---

## Features by Phase

### Phase 1: Job Match Scoring
- Match percentage (0-100%) using AI/embedding analysis
- Gap analysis: "Missing: Kubernetes, AWS Lambda, GraphQL"
- Actionable suggestions: "Add 'Built microservices with Kubernetes' to Experience"
- Side-by-side view: Resume bullets vs JD requirements

### Phase 2: ATS Compatibility Check
- ATS score based on formatting analysis
- Detection: images, tables, columns, icons, fancy fonts
- Fix list: "Remove table from Experience section"
- Preview: Plain text parse (what ATS sees)

### Phase 3: Application Tracker
- Status workflow: Applied → Phone Screen → Technical → Onsite → Offer/Rejected
- Notes per application: "Recruiter: Sarah, sarah@company.com"
- Reminders: "Follow up on Acme application (applied 2 weeks ago)"
- Timeline: Visual calendar of application activity

### Phase 4: Insights Dashboard
- Skills word cloud or bar chart
- Experience timeline: Interactive career progression
- Keyword density: "Python mentioned 12x, React 8x, Kubernetes 2x"
- Funnel metrics: "50 applied → 5 interviews → 1 offer (2% conversion)"

### Phase 5: A/B Testing
- Create variants: "Variant A: Backend-focused, Variant B: Full-stack"
- Track per variant: "A: 20 apps, 1 interview | B: 30 apps, 4 interviews"
- Statistical calculator: "Variant B is 95% better (significant)"
- Auto-pause: "Pause Variant A? It's underperforming by 80%"

### Phase 6: Industry Benchmarking
- Percentile ranking: "Top 35% for Senior Backend Engineer"
- Salary estimate: "$130k-$155k based on skills/location"
- Skills gap: "Missing for Staff level: System design, leadership"
- Market demand: "Python + React demand up 23% this quarter"

## Technical Considerations

### Research Questions

1. **Match Scoring Algorithm**
   - TF-IDF similarity?
   - Sentence embeddings (OpenAI, Cohere)?
   - Hybrid approach (keywords + semantics)?

2. **ATS Compatibility**
   - Which ATS systems to test against? (Workday, Greenhouse, Lever, Taleo)
   - What parsing rules to implement?
   - Should we generate ATS-friendly templates?

3. **Application Tracking Data**
   - Local storage (IndexedDB) or backend database?
   - Sync across devices?
   - Import from email/LinkedIn?

4. **Data Visualization**
   - Chart.js vs Recharts vs Visx?
   - Server-side rendering for charts?
   - Real-time updates?

5. **A/B Testing Statistics**
   - Chi-squared test for significance?
   - Minimum sample size requirements?
   - Bayesian vs frequentist approach?

6. **Benchmarking APIs**
   - Salary data: Levels.fyi, Glassdoor, Payscale API?
   - Skills demand: LinkedIn API, Indeed API?
   - Industry standards: O*NET, Bureau of Labor Statistics?

## Success Metrics

**v1.2 is successful when:**

1. Users can see match score for any JD within 5 seconds
2. ATS check identifies 90%+ of formatting issues
3. Users track 80%+ of applications in the tracker
4. A/B testing shows statistically significant results after 20+ applications
5. Benchmarking data is within 10% of actual market rates

---

## Dependencies & Risks

### Dependencies
- Phase 3 (Application Tracker) needed for A/B Testing (Phase 5)
- Phase 3 data needed for Insights Dashboard (Phase 4)
- External APIs for benchmarking (Phase 6)

### Risks
- **API Costs:** Salary/market data APIs may be expensive
- **Privacy:** Application tracking stores sensitive job search data
- **Accuracy:** Match scoring must be transparent about limitations
- **Sample Size:** A/B testing requires many applications for significance
