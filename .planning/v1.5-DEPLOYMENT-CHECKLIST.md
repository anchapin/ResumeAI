## 🌐 Production Deployment

### Step 1: Pre-Deployment

```bash
# Backup database
pg_dump -h localhost -U resumeai resumeai > backup_$(date +%Y%m%d_%H%M%S).sql

# Verify backup
pg_restore --list backup_$(date +%Y%m%d_%H%M%S).sql

# Set production environment
export ENVIRONMENT=production
export LINKEDIN_CLIENT_ID=production_client_id
export LINKEDIN_CLIENT_SECRET=production_client_secret
export ADZUNA_APP_ID=production_app_id
export ADZUNA_APP_KEY=production_app_key
```

### Step 2: Deploy

```bash
# Run migrations
alembic upgrade head

# Deploy new version
docker-compose up -d --force-recreate resume-api

# Wait for health check
until curl -f http://localhost:8000/api/v1/health; do sleep 1; done

# Start scheduler (should auto-start with application)
# Verify scheduler is running
docker-compose ps | grep scheduler
```

### Alert Configuration (Prometheus)

```yaml
groups:
  - name: v1.5_job_board
    rules:
      - alert: LinkedInOAuthHighErrorRate
        expr: rate(linkedin_oauth_failed_total[5m]) / rate(linkedin_oauth_initiated_total[5m]) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "LinkedIn OAuth error rate high"
          
      - alert: JobFetchHighErrorRate
        expr: rate(jobs_fetch_failed_total[5m]) > 0.2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Job fetch error rate high"
          
      - alert: EmailSendHighFailureRate
        expr: rate(emails_failed_total[5m]) / rate(emails_sent_total[5m]) > 0.1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Email send failure rate high"
          
      - alert: SchedulerNotRunning
        expr: alert_scheduler_running == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "Alert scheduler not running"
```

## 🔄 Rollback Procedure

### If Issues Occur

```bash
# 1. Stop new deployment
docker-compose stop resume-api

# 2. Restore previous version
docker-compose up -d resume-api:previous_version

# 3. Verify rollback
curl https://api.yourdomain.com/api/v1/health

# 4. Check version
curl https://api.yourdomain.com/api/v1/health | jq .version
```

### Database Rollback (if needed)

```bash
# Restore from backup
psql -h localhost -U resumeai resumeai < backup_YYYYMMDD_HHMMSS.sql

# Or downgrade migration
alembic downgrade -1
```
