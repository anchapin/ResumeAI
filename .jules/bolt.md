## 2026-06-05 - Avoiding N+1 Queries in SQLAlchemy with length calculations
**Learning:** When eagerly loading relationships with `selectinload` to avoid N+1 queries in SQLAlchemy, calculating the relationship count using `len()` directly on the eagerly loaded model attribute (e.g., `len(team.members)`) is significantly more efficient than executing a separate `.count()` query for each iteration, and reduces queries from 2N+1 to a single constant query. Crucially, applying `.unique()` to the executed result scalars is required when eager loading with joins to avoid duplicate entities.
**Action:** Always inspect loops in route handlers that perform database queries. If counting or aggregating related records, verify if eager loading via `selectinload` combined with in-memory Python operations like `len()` can eliminate the N+1 queries.
